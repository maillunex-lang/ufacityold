# Оценка PWA (iPhone) — этап 1

Дата: 2026-11-04. Движок: Godot 4.7-stable, рендерер GL Compatibility (WebGL 2), экспорт Web без потоков
(`thread_support=false`, не требует заголовков COOP/COEP). Сборка: `client/export_presets.cfg`, пресет «Web».

## Находки и исправления
1. **`http.FileServer` в Go ломал офлайн-оболочку**: `/index.html` перенаправляется на `./`, service worker кэширует «redirected»-ответ, и браузер отказывает в навигации (`ERR_FAILED`). Исправлено: `index.html` отдаётся напрямую (тест в `app_test.go`). Статика через nginx этой проблемы не имеет.
2. **Первый визит не кэширует ядро**: service worker берёт wasm/pck в кэш только при втором открытии (особенность схемы Godot). Первая загрузка всегда идёт по сети.
3. **Англоязычная офлайн-страница** Godot по умолчанию («You are offline») — нужна своя русская (`progressive_web_app/offline_page`).
4. **Размер ядра**: 39,5 МБ без сжатия. Без gzip/brotli первый запуск по мобильной сети тяжёлый. Нужно сжатие: заранее сжатые файлы (рекомендуется, без нагрузки на 1 vCPU) или `gzip` в nginx для `application/wasm` внутри нашего `location` (глобальные настройки не трогать). **Не реализовано и не проверено на VPS.**
5. Тестовые иконки PWA — временные.

## Не проверено (честно)
- **Safari на iPhone не проверялся вообще.** В песочнице нет WebKit, iPhone нет. Всё выше — только Chromium.
- Реальная производительность: в песочнице программный WebGL (~16 кадров/с) — к телефону отношения не имеет.
- Особенности iOS, которые известны заранее и требуют проверки на устройстве:
  - **Память.** Файлы `user://` в Web-версии Godot живут в памяти и зеркалируются в IndexedDB; для настоящих ресурсов (7 моделей, текстуры, фоны) это может упереться в лимит памяти вкладки Safari. Сейчас 13 МБ заглушек — риска не показывает.
  - **Хранилище.** Safari может очищать данные сайта, если его не открывали около недели и он не добавлен на экран «Домой»; в установленном PWA лимиты мягче.
  - **Звук** на iOS стартует только после касания (звука в игре пока нет).
  - Блокировка ориентации из манифеста на iOS может игнорироваться.
  - Установка — вручную («Поделиться → На экран Домой»), без системного приглашения.
- Обновление версии: service worker обновляется при изменении сборки, но активируется после перезапуска; нужна проверка совместимости версий клиента и сервера (общая задача, пока нет).
- Размещение на VPS: раздача `/LunexGame/play/` реализована в сервере (переменная `LUNEXGAME_WEB_DIR`), но в боевом окружении **не включена** и в деплой не встроена.

## Вывод
**Технически PWA на этом движке и этой кодовой базе работает** — клиент, вход, ресурсы, бой и оболочка в браузере подтверждены (Chromium). Решающие риски лежат вне проверенного: **память и хранилище Safari при настоящих ресурсах**, первая загрузка 10+ МБ ядра и поведение на реальном iPhone. Рекомендация: оставить Godot (Compatibility), PWA делать после Android-версии; перед этим дать владельцу открыть тестовую страницу на iPhone (понадобится развернуть Web-сборку и включить сжатие) и замерить память на сборке с реальными ресурсами.
