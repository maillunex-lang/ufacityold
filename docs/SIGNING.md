# Подпись APK постоянным ключом

**Зачем.** Android ставит обновление поверх установленной игры только если APK подписан тем же ключом. Сейчас каждая
сборка подписана одноразовым ключом CI, поэтому перед новой установкой приходится удалять старую (и терять локальные данные).
Постоянный ключ нужен до функции «обновление из игры». **Потеря ключа = все установленные копии придётся удалять и
ставить заново.** Резервная копия обязательна.

**Принцип безопасности.** Приватный ключ не хранится в репозитории и не передаётся в переписку/ассистенту. Он живёт в
секретах GitHub (окружение `android-signing`, доступное только для ветки `main`) и в вашем менеджере паролей.
Проверки pull request ключа не получают.

## Шаг 1. Создать ключ (на вашем VPS, ничего не устанавливается)
```
mkdir -p ~/lg-signing && cd ~/lg-signing && umask 077
read -r -s -p "Придумайте длинный пароль ключа: " KSPW; echo; export KSPW
openssl req -x509 -newkey rsa:4096 -sha256 -days 10000 -nodes -keyout key.pem -out cert.pem -subj "/CN=LunexGame/O=LunexGame/C=RU"
openssl pkcs12 -export -inkey key.pem -in cert.pem -name samraya -out release.p12 -passout env:KSPW
```
(Пароль при вводе не отображается и не попадает в историю команд.)

## Шаг 2. Показать значения для GitHub
```
echo "=== ANDROID_KEYSTORE_BASE64 (секрет) ==="; base64 -w0 release.p12; echo
echo "=== ANDROID_CERT_SHA256 (не секрет) ==="; openssl x509 -in cert.pem -noout -fingerprint -sha256
```

## Шаг 3. Сохранить резервную копию — ДО удаления файлов
Скопируйте в менеджер паролей (и во второе независимое место, например зашифрованную заметку):
1. весь текст `ANDROID_KEYSTORE_BASE64`;
2. пароль ключа;
3. алиас `samraya`.
Это всё, что нужно для восстановления: файл ключа получается командой `base64 -d`.

## Шаг 4. Добавить в GitHub
В репозитории `maillunex-lang/ufacity`:
- **Settings → Environments → New environment** → имя `android-signing` → *Deployment branches and tags* → *Selected branches* → добавить `main`.
- В этом окружении **Environment secrets**:
  - `ANDROID_KEYSTORE_BASE64` — текст из шага 2;
  - `ANDROID_KEYSTORE_PASSWORD` — ваш пароль;
  - `ANDROID_KEY_ALIAS` — `samraya`.
- **Settings → Secrets and variables → Actions → Variables → New repository variable**:
  - `ANDROID_CERT_SHA256` — отпечаток из шага 2 (строка после `sha256 Fingerprint=`). Это публичная информация, она нужна для сверки: если ключ подменят, сборка упадёт.

## Шаг 5. Удалить ключ с сервера
```
shred -u key.pem cert.pem release.p12; cd ~; rmdir lg-signing; unset KSPW
```
(Только после того, как резервная копия из шага 3 сохранена и проверена.)

## Как это работает в CI
- Любая сборка (в том числе pull request) собирает debug-APK одноразовым ключом и дополнительно проверяет, что release-экспорт и подпись работают. Постоянный ключ в них недоступен.
- Задача `release-apk` запускается только для push в `main`, в окружении `android-signing`. Она собирает release-APK, подписывает постоянным ключом, сверяет отпечаток с `ANDROID_CERT_SHA256` и размер (≤ 90 МиБ) и публикует артефакт `lunexgame-release-apk-<sha>` (хранится 30 дней).
- Если секреты не заданы, задача завершается без сборки с пояснением в логе.
- Номер версии Android (`versionCode`) берётся из номера запуска CI и растёт с каждой сборкой, чтобы обновление поверх установленного работало.

## Что учесть
- Первый раз release-APK придётся ставить после удаления текущей установки (другой ключ). Дальше обновления идут поверх.
- Пользователь с правом записи в репозиторий может изменить workflow и получить доступ к секретам окружения — ограничьте круг людей с записью.
- Смена ключа позже возможна только в рамках схемы смены ключа Android (rotation) либо потребует переустановки всеми игроками.
