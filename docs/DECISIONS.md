# Решения
## Утверждены заказчиком
Структура игры, бой, экономика, VIP, гильдии, админка — по исходному ТЗ (раздел 5); ТЗ является источником, здесь не дублируется.

## Приняты на этапе 0 (предложения инженера, подлежат подтверждению после обследования VPS)
1. **Сервер на Go, один статический бинарник**, без Docker: проще изолировать (systemd + отдельный пользователь), нет зависимостей. Docker не устанавливается.
2. **Префикс `/LunexGame/`** зашит в маршруты; корневые `/api`, `/assets`, `/admin` не используются (тесты это проверяют).
3. **Публикация через существующий nginx** (`location ^~ /LunexGame/`, include-сниппет), порт — loopback, выбирается при установке и проверяется на занятость. Новых публичных портов нет.
4. **Доставка по SSH с forced command** + `restrict`; пользователь `lunexgame-deploy`, sudo только на `systemctl restart lunexgame.service`. Host key закрепляется в секрете `DEPLOY_KNOWN_HOSTS`. Бинарник проверяется по SHA-256, релиз = commit SHA.
5. **Данные вне релизов**: `/opt/lunexgame/data|assets|backups` деплой не затрагивает.
6. **СУБД: SQLite (WAL), отдельный файл в /opt/lunexgame/data** (решено по обследованию: 1 vCPU/1.9 ГБ ОЗУ, чужая Postgres в контейнере agroapp не используется). Драйвер — чисто-Go (modernc.org/sqlite), CGO не нужен. Пересмотреть при росте нагрузки. БД — отдельная, `lunexgame_*`, не из интернета. Пока БД не подключена, `/api/health` её не заявляет.
7. **Основная ветка**: в репозитории нет ни одной ветки; workflow настроен на `main`. Нужно подтверждение.
8. **Автодеплой выключен по умолчанию**: job `deploy` запускается только при `vars.DEPLOY_ENABLED == 'true'` и environment `production`.
9. **Миграции**: только вперёд, неразрушающие применяются автоматически после бэкапа; разрушающие — вручную. Откат приложения не откатывает БД; каждая миграция совместима с предыдущей версией приложения (expand/contract).

## Этап 1
10. **Движок клиента: Godot 4.5-stable, рендерер GL Compatibility** (мобильный и веб-экспорт, малый размер). Обоснование подтверждено частично: Android-экспорт arm64 даёт 26 МиБ с пустой сценой; пригодность для 3D-боя и Web/PWA на iPhone **ещё не проверена прототипом**.
11. **Версия Godot закреплена в CI** (`GODOT_VERSION`); смена — отдельное решение.
12. **Целевое устройство разработки: iQOO 15R, Android 17** (со слов владельца). targetSdk сборки 35; совместимость с Android 17 проверяется только установкой на устройство.
13. **Подпись APK:** пока одноразовый debug-ключ CI (каждая сборка подписана новым ключом, обновление поверх установленной невозможно — удалять старую). Постоянный ключ нужен до функции обновления из игры.
14. **Гостевой токен** — 256 бит случайных, на сервере хранится SHA-256; в клиенте — в `user://` (песочница приложения). Лимит создания гостей: 10/мин на IP.
15. **Резервные копии БД** перед миграциями: `VACUUM INTO` в `/opt/lunexgame/data/backups` (служба имеет запись только в data/ и assets/).
16. **Godot переведён 4.5 → 4.7-stable** по решению владельца (быстрее). Run 41886913975 (commit 4138442): импорт, headless-вход клиента на настоящий сервер (BOOT_OK), экспорт Android APK и проверка размера ≤ 90 МиБ — пройдены. Скорость 4.7 относительно 4.5 не измерялась. Артефакт APK теперь из этого запуска.

17. **Ресурсы:** манифест `GET /LunexGame/api/assets/manifest` (путь, размер, SHA-256, группа = первый каталог пути; `start` — до входа, остальное в фоне), файлы `GET /LunexGame/assets/<путь>` с поддержкой Range. Публикуются только файлы внутри групповых каталогов `AssetsDir`; скрытые файлы и файлы в корне не публикуются; пути берутся из индекса, не из ФС. Диск перескандируется не чаще раза в 5 с.
18. **Заглушки ресурсов:** детерминированно генерируются сервером (не лежат в репозитории), помечены `placeholder:true`, перекрываются реальным файлом с тем же путём. Удалить после появления настоящих ресурсов.
19. **Докачка:** клиент качает файл кусками по 1 МБ с заголовком Range в `.part`; перед использованием проверяется SHA-256; `.part` от другой версии файла отбрасывается. Состояние — `user://assets_state.json`.
20. **Проверка целостности:** при обычном запуске — наличие и размер; полная перепроверка хэшей включается переменной `LUNEXGAME_VERIFY_FULL=1` (в игре — будет кнопка/условие позже). Решение о периодической полной проверке отложено.

21. **Бой (прототип):** сервер рассчитывает бой целиком в игровом времени (шаг 100 мс, лимит 90 с, без случайности — детерминированно) и отдаёт запись событий; клиент проигрывает. Главная способность в этой схеме срабатывает автоматически при полной энергии; ручной запуск по портрету потребует боя в реальном времени (этап 2). Выбрано владельцем 2026-11-04.
22. **Правила энергии, реализованные и покрытые тестами:** старт 0; растёт от нанесённого обычной атакой урона, полученного урона и фактически восстановленного здоровья (избыточное лечение не считается); главная способность тратит весь запас; её урон и лечение энергию владельцу не возвращают (получатели лечения энергию получают); коэффициенты — структура `Energy`, пока константы (вынос в админку — этап 5). Таймаут и взаимное уничтожение — поражение атакующего.
23. **Временный баланс `proto-1`:** 5 героев игрока и 5 врагов, здоровье ×3 для длительности ~50 с. Версия баланса записывается в бой (закрепление на старте). Не финальный контент.
24. **Хранение боёв:** таблица `battles` (миграция 0002), бой доступен только владельцу. Награды ещё не начисляются, поэтому защита от двойной награды пока не нужна и не проверена.
